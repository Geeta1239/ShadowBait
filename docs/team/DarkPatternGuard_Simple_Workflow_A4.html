DarkPatternGuard — Simple Working Flow

Follow these steps in order. Each step must work before moving to the next step.

START: Build the website → scan it → detect patterns → calculate risk → show the result
1
Member 4 — Demo Website
Build the DarkShop website
  • Create product, cart, and checkout pages.
  • Add prices, discount, timer, and “Only 2 left” text.
  • Add a checked “Add ₹50 donation” checkbox.
  • Give the team the website URL and element IDs.
Result: A working website to test
Checkpoint: DarkShop opens and the checked donation checkbox is visible.
↓
2
Member 1 — Scanner
Open and inspect the website
  • Open the URL using Playwright and Chromium.
  • Read the page title, URL, HTML, and visible text.
  • Find buttons, forms, checkboxes, prices, timers, and links.
  • Record selectors and element positions.
Result: Structured webpage data
Checkpoint: The scanner can find #donation, #scarcity-text, and #offer-timer.
↓
3
Member 1 — Evidence
Save states, screenshots, and evidence
  • Check whether the donation checkbox is already checked.
  • Capture product, cart, checkout, and full-page screenshots.
  • Save HTML, text, selectors, and bounding boxes.
  • Create the first DP01 Basket Sneaking candidate.
Result: Evidence JSON + screenshots
Checkpoint: DP01 contains text, selector, page, screenshot, and checked=true.
↓
4
Member 2 — Detection
Understand and classify the evidence
  • Read the scanner’s text and evidence JSON.
  • Confirm Basket Sneaking.
  • Detect False Urgency using timer and scarcity keywords.
  • Detect Confirm Shaming from guilt-based wording.
  • Add DeBERTa only after the simple rules work.
Result: Pattern + confidence + evidence
Checkpoint: DP01, DP02, and DP03 findings use the same JSON format.
↓
5
Member 3 — Backend
Connect everything through the API
  • Create POST /scan and the result/evidence endpoints.
  • Call Member 1’s scanner and Member 2’s detector.
  • Save scans and findings in SQLite.
  • Calculate risk score and risk level.
  • Add compliance category and recommendation.
Result: Complete result JSON from the API
Checkpoint: POST /scan returns findings, risk, evidence, and recommendations.
↓
6
Member 4 — Frontend
Show the result to the user
  • Add the URL input and Start Scan button.
  • Show scan progress while the backend is working.
  • Display risk score, patterns, confidence, and severity.
  • Show the screenshot, selector, and highlighted element.
  • Show the ethical Before → After recommendation.
Result: A usable judge-ready dashboard
↓
7
Everyone — Final Integration
Run the complete demo and test it
  • Enter the DarkShop URL in the dashboard.
  • Run the scan from beginning to end.
  • Verify evidence and the heatmap.
  • Test a clean page to prevent false findings.
  • Add remaining patterns only after DP01 works fully.
FINAL: Detect → Explain → Fix
Correct order: Website → Scanner → Detection → Backend → Dashboard → Demo
